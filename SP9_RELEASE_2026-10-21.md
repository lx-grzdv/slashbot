## Корневые проблемы дня

### 1. Открытие Updates ломалось на коротком EN-only клике

Типичная ошибка утра:

`Updates: Не удалось открыть Updates: edited: Locator.click: Timeout 5000ms exceeded`

`_open_history()` искал только кнопку `^Edited` и меню `Actions` /
`Updates & analytics` с таймаутом 5 с. При медленном UI или русской подписи
(`Изменено`, `Действия`, `Обновления`) карточка оставалась с
`content_complete=true`, но без `comments_complete` / `updates_complete`.

**Что изменено в коде:**

- кнопка edited: `^(Edited|Изменено)`, timeout **12 с**;
- Actions: `^(Actions|Действия)$`; пункт меню: Updates / Updates & analytics /
  Обновления; timeout **8 с**;
- ожидание панели **12 с**;
- тесты в `test_sp9_card_recovery.py` обновлены под regex.

После правки отдельный проход прочитал **31 из 34** за ~3 минуты. Три оставшиеся
упали уже не на открытии, а на:

`Не все комментарии в истории удалось прочитать`

(пагинация/полнота листа комментариев внутри уже открытого Updates).

### 2. Неполный выпуск ушёл и закрыл день для автоповторов

Как и 16/19/20 октября: `last_successful_send` + `--skip-if-sent-today`
фиксируют доставку, в том числе с warning. В 12:37 покрытие было ~32 полных /
34 неполных при 66 задачах. Это снова подтверждает бэклог **C**: нет автодочитывания
и `edit` того же message id.

Фикс лимита Telegram от 20.10 **сработал**: редактор не упал на «не помещаются»;
вместо этого сработал `split_digest` → два сообщения. Новый дефект peak–end:
часть 2 состояла почти целиком из списка непрочитанных карточек.

### 3. Наивный recovery затёр утренние board-diff строки

Пересборка только из `activity_events(snapshot, baselines, seen)` после
дочитывания добавила Updates-события, но **выбросила** факты, которые утром
пришли из сравнения доски/свойств и уже были в первой версии поста:

- EEAT. Страница «О компании» — назначения Сергей/Паша, снят Алексей;
- Экран входа в PWA — In Progress, назначен Алексей.

Одновременно авторедактор после полного Updates раздул строки (длинный EN
бриф Investment, простыня Halloween BOO25/BOGOBOO, сценарий хука SMM 3) —
против [редполитики](SP9_EDITORIAL_POLICY.md) (короткий русский итог).

### 4. Codex не закрыл операционный день

Сессия с 10:52 верно диагностировала старт и прогресс, затем ушла в недоступные
облачные субагенты и проектирование параллельных воркеров. По просьбе
пользователя остановилась, **не** доведя выпуск, recovery и правку поста.
Сборщик при этом продолжал работать сам — агент не был блокером доставки,
но и не выполнил роль «закрыть день».

## Выводы

1. **Класс отказа сместился.** Вчера ломало «текст >3900 → raise». Сегодня
   доставка прошла, но снова через неполное Updates и ручной контур качества.
2. **Opener Updates — узкое место дня.** EN-only + 5 с даёт десятки ложных
   «неполных» при живой сессии; RU/длиннее timeout резко поднимает успех
   повторного чтения. Пагинация комментариев у трёх карточек — отдельный долг.
3. **Warning в `split_digest` вреден.** Список из 34 ссылок не должен становиться
   отдельным сообщением; в идеале — одна строка в футере или отсутствие части 2.
4. **Recovery ≠ merge board + activity.** Дочитывание Updates нужно **дополнять**
   проверенный утренний editorial/board-diff, а не заменять его сырым
   `prepare_editorial_digest` только по новым activity-событиям.
5. **Бэклог C и A подтверждены.** Без авто-edit после дочитывания и без сжатия
   UI/сценариев день снова закрывается руками. Бэклог B: долгий pid с 10:51
   держал job `running` мимо 11:50, но в итоге сам доставил — хуже был бы
   сценарий «висит без отправки» как 20.10.
6. **День не автономен.** Автоотправка с warning + ручные сжатие, recovery и
   идеальная правка. В счётчик пяти полных автономных выпусков не входит.

## Как не нарываться снова

Дополняет чеклист [20 октября](SP9_RELEASE_2026-10-20.md#как-не-нарываться-снова).

| Риск | Как не попасть |
| --- | --- |
| Снова 30+ карточек без Updates | После деплоя opener EN/RU смотреть stderr/audit; warning >5 карточек = recovery в тот же день |
| Часть 2/2 = только warning | Не оставлять; сжать в одну строку или edit до одного сообщения |
| Recovery затёр утренние строки | Мержить утренний editorial + новые activity; сверять lost links before/after |
| Агент ушёл в субагентов | Операционный день: пост → покрытие → edit; ускорения — после закрытия выпуска |
| 3× «не все комментарии» | Отдельная задача на пагинацию листа; не путать с opener |

Чеклист к ~12:00 (как 20.10) плюс:
